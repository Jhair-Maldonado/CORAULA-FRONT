# N2-F2: planilla administrativa, corrección e historial

`/administrador/notas` reutiliza secciones y cursos reales, bimestres del periodo seleccionado, Axios/JWT y el parser N2 existente. ADMINISTRADOR consulta y corrige; DIRECTIVO solo consulta planilla e historial. Solo una celda MANUAL activa, con gradeId y nota persistida, en bimestre ABIERTO ofrece corrección. Cero es corregible; null es pendiente. PA permanece pendiente y de solo lectura porque el contrato no aporta resultados PA.

Contratos revisados en `CORAULA-BACKEND/develop/docs/manual-grades-n2.md` (blob `3a07310407db1a256614547ac200edefd1c1c4f9`): GET `/api/v1/management/section-courses/{sectionCourseId}/bimesters/{bimesterId}/criterion-grades`, PATCH `/api/v1/management/criterion-grades/{gradeId}` con exclusivamente `{grade, reason, expectedGrade}`, GET `/api/v1/management/criterion-grades/{gradeId}/history`. Exige HTTP 200, respuestas completas y contexto/IDs coherentes. Historial muestra valores, motivo, usuario y fecha; creación no fabrica historial.

Validación de 0–20, máximo dos decimales sin redondeo, motivo obligatorio y cambio efectivo. expectedGrade procede de la celda persistida. Un lock síncrono impide doble envío. Cada intento de PATCH invalida el formulario y recarga GET; solo confirma éxito si devuelve el mismo gradeId con la nota propuesta. 409 explica conflicto sin sobrescribir ni reintentar. Red/respuesta ambigua no produce éxito ni retry automático; fallo de recarga exige actualizar antes de otra corrección. Cambios de sección/curso/bimestre invalidan callbacks síncronamente y descartan respuestas tardías. Diálogos reutilizan foco, teclado y Escape existentes.

Pruebas focalizadas de servicio/componentes con mocks exclusivamente en tests: 13/13 PASS para HTTP/DTO, contextos reales, criterios dinámicos, cero/null, PA, permisos, estados/inactivos, validaciones, conflicto, historial, confirmación por recarga, fallo/ambigüedad, doble envío y respuestas tardías. Validación final: npm test 63/63 PASS sin omisiones, lint PASS (17 advertencias preexistentes, cero errores), build PASS y git diff --check PASS. La suite completa se ejecutó una sola vez al finalizar. Node falló al iniciar los tests dentro del sandbox (uv_os_get_passwd/ENOMEM); la ejecución autorizada fuera del sandbox pasó.

`BROWSER_E2E: NOT_RUN`: sin infraestructura de navegador/backend/PostgreSQL aislados; pendiente recorrido visual, responsive y persistencia real con ambos roles. No se usan Supabase compartido ni datos reales para pruebas. No hay cambios backend/migraciones, creación administrativa de primeras notas o N3-B. Riesgo heredado del contrato: expectedGrade no detecta ABA; no se introduce un control de versión inexistente.
